Photocurrent emulator: 10:1 mirror pair

Split into two schematics. mirror_pair.sch is the cell: four transistors and four pins, nothing else, so it can later drop into the Tiny Tapeout wrapper. tb_mirror_pair.sch is the testbench: it instantiates the cell and holds every source, the ground, the models and the simulation commands.

2 · Testbench tb_mirror_pair.sch

The cell appears as one box (its generated symbol). All sources live out here; gnd.sym on the VSS net makes it SPICE node 0. R1/C1 are the Tiny Tapeout analog-pin model (500 Ω switch, 5 pF pad): invisible in the DC sweeps, a ~0.2 µs time constant at 1 µA in the transient.

For the real test chip the same testbench pattern repeats one level up: the cell's VDD/VSS become the wrapper's VDPWR/VGND, IIN becomes analog pin ua[0], and the bench current source is on the breakout board.

Control block (code_shown value, testbench only)

.control
save all
* sweep 1: 100 nA .. 100 uA, linear steps, plotted on log axes (ngspice has no log sweep)
dc Iin 100n 100u 100n
plot abs(i(vout)) xlog ylog title 'Iout vs Iin (expect Iin/100)'
let ratio = abs(i(vout))/abs(i(vamm))
plot ratio xlog title 'mirror ratio Iout/Iin (expect 0.01)'
* sweep 2: low end, 10 nA .. 1 uA, where the mirror starts to drift
dc Iin 10n 1u 10n
let ratio_lo = abs(i(vout))/abs(i(vamm))
plot ratio_lo xlog title 'mirror ratio at low currents'
* sweep 3: same as 1 at Vout = 0.3, 0.9, 1.5 V (output resistance of M4)
dc Iin 100n 100u 100n Vout 0.3 1.5 0.6
plot abs(i(vout)) xlog ylog title 'Iout at Vout = 0.3 / 0.9 / 1.5 V'
* leakage floor: input off, what still comes out
alter Iin = 0
op
print i(vout)
* pin model only matters in time: step 1 -> 10 uA through the 500 ohm / 5 pF pad
alter Iin dc = 1u
alter @Iin[pulse] = [ 1u 10u 1u 1n 1n 5u 10u ]
tran 10n 12u
plot v(pad) v(iin) title 'pad and iin voltages, step through the pin model'
plot abs(i(vout)) title 'Iout settling after the step'
.endc

Plot 1 = Iout, plot 2 = mirror ratio (≈0.01, rolling off below a few hundred nA), plot 3 = Iout at 0.3 / 0.9 / 1.5 V, which shows XM4's output resistance. The internal node is v(x1.i10) if you labelled it.

Build order

  1. Start xschem inside the project's xschem/ folder. "+" → File → Save As mirror_pair.sch.
  2. Place XM1–XM4, set L/W/mult with Q; Shift+F flips XM1 and XM3. Wire everything, bodies included.
  3. Add the four pins (ipin.sym ×3, opin.sym ×1), set each lab=. Save.
  4. Press A (Symbol → Make symbol from schematic). xschem writes mirror_pair.sym next to the .sch with the four pins on a box.
  5. "+" → Save As tb_mirror_pair.sch. Shift+I → mirror_pair.sym (the project folder is on the library path through its xschemrc).
  6. Add V1, Iin, Vamm, Vout, one gnd.sym on VSS, the net labels, corner.sym and code_shown.sym. Netlist (N), Simulate.
  7. Pin model (course step "Add the model of the Tiny Tapeout analog pin"): delete the wire from Vamm's bottom pin to IIN. Shift+I → devices/res.sym, R to rotate horizontal, drop it on that path, Q → value=500. Shift+I → devices/capa.sym below the Vamm-side node, Q → value=5p, wire its bottom to the VSS rail. Put lab_wire lab=pad on that node. The isource needs value="dc 1u pulse(1u 10u 1u 1n 1n 5u 10u)" for the transient, or the alter lines in the control block set it.
  8. To edit the cell later, select X1 and press E (descend), Ctrl+E to come back up.

Output voltage 0.3 → 1.5 V shifts the ratio by ~5 % (M4 output resistance). Three cells chained (÷10⁶): 10 µA at the pin gives 16.5 pA at the pixel, +65 % over nominal because the three errors multiply; usable range at the pixel ≈ 2.5–140 pA for 1–100 µA at the pin. Pads leak nanoamps, so the division must happen on chip.

What to look for

Ratio close to 0.01 above ~1 µA (strong inversion, matched units). Below that XM2 and XM4 slide into subthreshold and the ratio drifts; that current is the lower limit at which this emulator stage can be trusted on the test chip. In the third plot a few percent change of Iout between 0.3 V and 1.5 V is normal for L=1 µm; double L on XM4 if it is worse. A second identical cell on IOUT later gives ÷104, which takes a 10 µA bench current down to the ~1 nA of a dark pixel.

Input current is far below the 4 mA Tiny Tapeout pin limit. For a 3.3 V tile use nfet_g5v0d10v5 / pfet_g5v0d10v5 with L ≥ 0.5 and V1 = 3.3.

Carried over from block 1 (so you don't hit it twice)

  • Start xschem from the project's xschem/ folder. Its xschemrc must append $env(PDK_ROOT)/$env(PDK)/libs.tech/xschem to XSCHEM_LIBRARY_PATH, otherwise every sky130_fd_pr/… symbol is "MISSING SYMBOL". set XSCHEM_START_WINDOW {} stops the demo sheet.
  • Two flavours of every transistor. nfet_01v8.sym / pfet_01v8.sym have a B pin you wire; nfet3_01v8.sym / pfet3_01v8.sym have no B pin and take the body net from the text attribute body=VSS / body=VDD. Both netlist the same; the 3-pin one keeps busy schematics clean, the 4-pin one survives a rail rename. If you rename VDD/VSS to the Tiny Tapeout names (VDPWR/VGND), every body= attribute must follow.
  • Pins. ipin, opin, iopin are identical for SPICE; the lab= text is the port name. Rails are ordinary pins inside a cell. Several lab_pin.sym flags with the same lab connect without a wire, which is how the cells below avoid wire crossings; one real pin per rail is still required.
  • Only the testbench has ground. No gnd.sym, sources, corner or control block inside a cell. In the testbench one gnd.sym on the VSS wire makes it SPICE node 0, and V1 makes VDD.
  • Make the symbol with A (Symbol → Make symbol from schematic) after the pins are final; changing a pin later means re-running A, or the testbench reports a pin mismatch. E on an instance descends, Ctrl+E returns.
  • ngspice dc sweeps are linear only. No dec keyword (that is LTspice). For a log picture use linear segments, one per decade, and xlog on the plot.
  • Currents are read through voltage sources. i(vout) works because Vout is a voltage source; a 0 V ammeter.sym gives a named current anywhere else. The x-axis of a current sweep is i-sweep, of a voltage sweep v-sweep.
  • Name internal nets with lab_wire.sym so they are not #net3; inside instance X1 they are reached as v(x1.name).
  • Run: N netlists, "Simulate" runs ngspice in a terminal, the .control block makes the plots, and the ngspice 1 -> prompt accepts setplot dc1, print …, wrdata file.txt …, quit.
  • Files edited outside xschem: close and reopen the schematic (or File → Reload) before saving, or the in-memory copy overwrites the edit.
  • Leakage and temperature. .temp 85 is °C. To see a floor: alter Iin = 0, op, print i(vout). Everything below ~10 pA at a node is leakage territory; pads leak nanoamps, so small currents never leave the chip.
  • A node with no DC path (behind a capacitor, like the differencing amp's input) needs .ic v(x1.x)=0 in the code block, or ngspice parks it wherever gmin says and the first microseconds are nonsense.
  • Mismatch Monte Carlo: set corner=tt_mm on corner.sym (open_pdks adds this section) and loop dowhile … reset … in the control block; each reset draws new random Vth offsets per device.
  • Share a schematic with https://xschem-viewer.com/?file=<GitHub blob URL of the .sch> after pushing. The red X on the repo's "gds" Action is expected until a layout exists in gds/.
