Block 4: switched-capacitor differencing amplifier

The change detector of the pixel: a capacitive-feedback inverting stage that amplifies changes of the photoreceptor output by C1/C2 and forgets the absolute level every time it is reset.

1 · Cell diffamp.sch

Node X has no DC path: it only touches two capacitors and the gate. That is the point of the circuit (the DC level of VIN is forgotten), and the reason the testbench needs an .ic line.

Why an NMOS reset and not the PMOS of the original DVS: at 1.8 V the amplifier parks around 0.6 V, and a PMOS switch with its body at 1.8 V has |Vth| ≈ 0.9 V there, so it barely conducts (we tried: reset took 8 µs and the gain came out with the wrong sign). An NMOS with 1.2 V of overdrive at that node closes hard. The price is a positive charge-injection step of ~40 mV at release, which is what pixel F's auto-zero cancels. Reset is active HIGH. For the real layout, capa.sym becomes sky130_fd_pr/cap_mim_m3_1.sym (≈ 2 fF/µm²: C1 = 10 × 10 µm, C2 = 3.2 × 3.2 µm) or the MOM finger caps from the GF180 plan.

Build order

  1. New schematic → Save As diffamp.sch.
  2. Place XMdn, XMdp (4-pin), XMr (nfet3_01v8.sym, body=VSS), C1 and C2 (devices/capa.sym, set value=).
  3. Wire C1 from VIN to X, C2 from X to VOUT, Mr across C2 (D on X, S on VOUT), Mdn gate on X, Mdn/Mdp drains on VOUT. Put a lab_wire lab=X on the node.
  4. lab_pin flags VDD on Mdp S, VSS on Mdn S. Add pins VDD, VSS, VDB, VIN, RST (ipin) and VOUT (opin). Save, A → diffamp.sym.
  5. New schematic → tb_diffamp.sch: place diffamp.sym, add V1, Vdb, Vrst, Vin, one gnd.sym, labels, corner.sym, code_shown.sym with the block (including the .ic line).
  6. N, Simulate. Three plot windows plus the printed gain.

What it means

This is the change detector. It does two things the pixel needs: it multiplies the small ΔVlog by ~9 so the comparators have something to work with, and it throws away the absolute level at every reset so the pixel only reports changes. In the full pixel the reset is pulsed by the handshake logic right after each event, so VOUT always restarts from the park point and the comparator thresholds are measured from there. The +40 mV reset offset is a systematic error: it is the same every time, so it effectively shifts the ON and OFF thresholds by 40 mV / 9 ≈ 4.5 mV at the input, which is more than your 3 % contrast step. That is the number pixel F's auto-zero is built to remove; for A/D/E you absorb it in the Von/Voff bias settings.

Things to try once it runs: C1 = 400f for gain ~18 (watch the output hit the rails), Vdb = 0.9 for lower current (reset gets slower), and Mr W = 1 to see the reset offset grow with the switch size.

Carried over from block 1 (so you don't hit it twice)

  • Start xschem from the project's xschem/ folder. Its xschemrc must append $env(PDK_ROOT)/$env(PDK)/libs.tech/xschem to XSCHEM_LIBRARY_PATH, otherwise every sky130_fd_pr/… symbol is "MISSING SYMBOL". set XSCHEM_START_WINDOW {} stops the demo sheet.
  • Two flavours of every transistor. nfet_01v8.sym / pfet_01v8.sym have a B pin you wire; nfet3_01v8.sym / pfet3_01v8.sym have no B pin and take the body net from the text attribute body=VSS / body=VDD. Both netlist the same; the 3-pin one keeps busy schematics clean, the 4-pin one survives a rail rename. If you rename VDD/VSS to the Tiny Tapeout names (VDPWR/VGND), every body= attribute must follow.
  • Pins. ipin, opin, iopin are identical for SPICE; the lab= text is the port name. Rails are ordinary pins inside a cell. Several lab_pin.sym flags with the same lab connect without a wire, which is how the cells below avoid wire crossings; one real pin per rail is still required.
  • Only the testbench has ground. No gnd.sym, sources, corner or control block inside a cell. In the testbench one gnd.sym on the VSS wire makes it SPICE node 0, and V1 makes VDD.
  • Make the symbol with A (Symbol → Make symbol from schematic) after the pins are final; changing a pin later means re-running A, or the testbench reports a pin mismatch. E on an instance descends, Ctrl+E returns.
  • ngspice dc sweeps are linear only. No dec keyword (that is LTspice). For a log picture use linear segments, one per decade, and xlog on the plot.
  • Currents are read through voltage sources. i(vout) works because Vout is a voltage source; a 0 V ammeter.sym gives a named current anywhere else. The x-axis of a current sweep is i-sweep, of a voltage sweep v-sweep.
  • Name internal nets with lab_wire.sym so they are not #net3; inside instance X1 they are reached as v(x1.name).
  • Run: N netlists, "Simulate" runs ngspice in a terminal, the .control block makes the plots, and the ngspice 1 -> prompt accepts setplot dc1, print …, wrdata file.txt …, quit.
  • Files edited outside xschem: close and reopen the schematic (or File → Reload) before saving, or the in-memory copy overwrites the edit.
  • Leakage and temperature. .temp 85 is °C. To see a floor: alter Iin = 0, op, print i(vout). Everything below ~10 pA at a node is leakage territory; pads leak nanoamps, so small currents never leave the chip.
  • A node with no DC path (behind a capacitor, like the differencing amp's input) needs .ic v(x1.x)=0 in the code block, or ngspice parks it wherever gmin says and the first microseconds are nonsense.
  • Mismatch Monte Carlo: set corner=tt_mm on corner.sym (open_pdks adds this section) and loop dowhile … reset … in the control block; each reset draws new random Vth offsets per device.
  • Share a schematic with https://xschem-viewer.com/?file=<GitHub blob URL of the .sch> after pushing. The red X on the repo's "gds" Action is expected until a layout exists in gds/.
